# 0. 設計動機

本文以原有的 [prengQvm 拼音方案](https://github.com/IemKwangqHraek/prengQvm) 爲基礎，整理目前採用的全拼與三拼。章節沿用原文的聲母、介音、韻核、韻尾、聲調、拼合方案與特殊字次序。設計要求與主要取捨見[設計取捨](設計取捨.md)，本文完整說明如何拼、如何按鍵。

全拼僅使用 26 個小寫拉丁字母，音節內不用隔音符號；保留原方案的 `r`、三等 A／B／C 拼式、`ae` 與 `ng/k`。三拼每音節恰按三鍵，分別表示聲母基幹、韻身及韻尾與聲調。同一片段查同一鍵，允許不同片段共鍵，由完整三鍵消歧。

**逐鍵立即解析不作需求。** 第一、第二鍵輸入後可以仍有多種片段解釋，第三鍵完成後再確定音節。輸入回饋採候選字詞及全拼提示的方向；保留小改版，不爲此增設 `kr/khr/hr/qr` 或恢復見組按三等性分寫。相關理由見[設計取捨](設計取捨.md)。

與原 GitHub 版相比，本版固定採用東一、侯 `wu`，豪 `oa+w`，蒸 C 韻核 `v`；取消莊組庚三歸二等。冬韻仍以 **`ow` 爲整體韻核**，不能把豪韻也寫成同一個韻核。`oa` 是豪韻的專用韻核記號，不要求解作兩個元音，也不據此斷言一個確定的 IPA 音值。

配套程式爲 [prengQvm.js](../prengQvm.js)，可直接用於新版[切韻音系推導器](https://nk2028.shn.hk/tshet-uinh-deriver/)。本版只提供輸出形式選項；音系與拼寫規則固定，避免切換全拼規則後誤用另一套三拼鍵表。

表 2. 介音與等類標記表；實際拼接須同第 6 節的縮合規則合看。

本表不把每個字母都當作獨立介音。二等 `r`、三 B 的 `r`、聲母中的 `r` 可以重合；東一、侯則直接使用整體韻核拼寫 `wu`，不另套原方案的 `o+u`。

三等的具體歸類如下：

- 鈍音依新版資料的 A／B／C 標註。支、侵、宵 B 按 C 類拼寫：支開 `ve`、合 `ue`，侵 `v+m/p`，宵 `ve+w`。本版所涵蓋的宵 B 沒有另一套合口拼式。
- 知、莊組三等強制用 B 拼式，**不參與上述支侵宵 B→C**。因此知 `trie`、兂 `tsrim`，不能套成 C 拼式。莊組庚三也保留三 B，如生 `sriaeng`。
- 章組及日、以母用 A 拼式；聲母自身的 `j/y/i` 已承擔相應標記。
- 其餘銳音遇前元音韻核按 A 拼式；非前元音韻核按 C 拼式。
- 蒸韻 B 用 `i`，其餘現用蒸韻地位用 `v`，如冰 `pring`、蒸 `tjvng`。莊組臻、殷（欣）韻沿原方案按 `i` 系拼寫。

##### 補充

這裏的「強制 A／B」是拼寫分類，並非斷言銳音具有與鈍音重紐完全相同的音位對立。程式直接讀取新版 `音韻地位.類`；舊程式對冰、幽等韻按字頭補判重紐的規則，不再疊加於已更新的地位標註之上。

幫組在一、二、四等及三 A／B 的開合不另強分；魚、虞、元、嚴凡等的三等拼式，按原規則結合韻類決定 `v/u`。程式不開啓「東、尤三 A 視作合口」：終仍爲 `tjung`，猷仍爲 `iu`。

# 6. 拼合方案

按「聲母＋介音及等類標記＋韻核＋韻尾＋聲調」組成全拼。

1. 先依聲母與韻類確定 `j/y` 等變體，以及三等拼式。章日以的聲母已承擔 A 類標記，不重複加一套 `i/y`；魚虞、元、陽等的 `vo/uo/va/ua` 在這些聲母後省去開頭的 `v/u`。
2. `i/e/ae` 系韻核依第 2 節添加 A／B 標記，或改用支侵宵的 C 拼式。高元音 `u/v` 不另外添加 A 類介音；聲母本身的 `j/i` 仍保留，如終 `tjung`、蒸 `tjvng`。
3. 合口拼式已有 `u/y` 時不再加 `w`；章日以由聲母變體承擔開合。其餘合口加 `w`，二等再加 `r`。
4. 相鄰重複的 `ii/yy/rr` 縮合爲 `i/y/r`；三拼另允許邊界 `jj→j`。這些是明定的縮合，不任意刪除其他字母。
5. 加韻尾及聲調。特殊音節按第 7 節處理。

例如生的 `sr + riae + ng → sriaeng`，知的 `tr + rie → trie`，爲的 `∅ + ue → ue`。三拼的書 `hj / jo / ∅ → hjo`、脂 `t / ji / i → tji`，則分別使用 `jj`、`ii` 邊界縮合。

正文按字分寫，音節之間可用空格；「不用隔音符號」指音節內的拼式，不限制文章中的空格與標點。

# 8. 全拼的其他補充

## 等呼的判斷

不能只看有沒有 `u/w` 就判定三等或合口：東一、侯的 `wu` 與冬的 `ow` 都是一等韻的固定拼寫。`r` 也須結合其餘拼式，區分二等與知莊或 B 類。

同樣，支侵宵 B→C 是拼寫歸併，不能從 `v/u` 反推上游類標註必爲 C。需要精確音韻地位時，使用逐地位對照表；本方案不以單個字母承諾所有音系標籤都能直接讀出。

## 容量與驗證範圍

原固定版《廣韻》樣本有 3,801 個地位；此次官方 `tshet-uinh 0.15.4` 內建資料有 3,804 個地位，兩者合併去重爲 **3,808 個**。新版比原樣本多 7 個地位，另有 4 個原樣本地位不在新版集合中；爲兼容既有資料，本次一併驗證。

這 3,808 個地位加補充「怎」，全拼與完整三鍵均無碰撞。多個同音字共碼是預期情況；此處無碰撞指不同的已驗證地位／補充音節。除爹的明定例外外，三段縮合均等於全拼。這不是所有理論上可構造地位、所有韻書及未收補充讀音的無碰撞證明。

本版證明 24／23／21 鍵可行，未宣稱 23 是第二鍵的最小值。鍵位已按指定語料及代理手感模型優化，但沒有實測校準或全局最優保證；逐項核對見 [check.json](../data/check.json)。

# 10. 推導程式與使用方法

## 在新版切韻音系推導器使用

1. 開啓[新版推導器](https://nk2028.shn.hk/tshet-uinh-deriver/)，新增一個空白自訂方案。
2. 將 [prengQvm.js](../prengQvm.js) 的全部內容貼入方案編輯區，取代原有範例。
3. 「輸出」可選全拼、三拼、三段、全拼及三拼；預設爲全拼。選「全拼及三拼」時，例如冬顯示 `towng〔FQL〕`。
4. 依一般推導器流程查字或標註文章；多音字仍按地位選讀。怎請使用下述本地補充查詢。

本檔是推導器所需的 JavaScript **函數體**，使用 `選項／音韻地位／字頭` 參數，沒有 `import/export`。不應直接執行 `node prengQvm.js`；本地執行使用配套入口。

## 本地查詢與重現

本倉庫的工具與 CI 使用 Node.js 22 以上版本；在本倉庫目錄執行：

```sh
npm ci --ignore-scripts
npm test
npm run derive -- --char 冬 豪 打 冷 地 爹 怎 𩦠
npm run derive -- --position 端一冬平 生開三庚平
```

查字會列出內建字表的所有讀音、來源地位、反切、全拼、三段及三鍵；怎由本方案補充條目返回，不捏造來源地位或反切。測試直接使用官方 `推導方案` 執行器及 `音韻地位` 對象，核對已提交的完整快照、當前資料、兼容地位、固定例字、全拼唯一性、三鍵唯一性與逐段局部性。`npm test` 不覆寫碼表；明確更新時執行 `npm run build:data`，審核 `data/` 差異後再提交。

目前固定依賴 `tshet-uinh 0.15.4`、`tshet-uinh-deriver-tools 0.2.0`。查核日期爲 2026-09-27；對應的推導器源碼版本與接口依據見 [sources.json](../data/sources.json)。之後升級資料庫，應重新跑測試，不僅更改版本號。

推導方案、查詢入口及基準編碼表之外，另提供可生成的 Rime 全拼／三拼 schema 及共用字詞典，詳見 [Rime 使用與改鍵](Rime使用與改鍵.md)。
