# 鍵位搜尋實現計劃

範圍：三段順序固定，不計記憶成本，多音字按去重後的中古全拼等概率分配。首輪固定現有共鍵組，分槽位重新分配至 26 個物理鍵；不修改現用鍵表。

1. **固定語料。** 下載公開、可追溯的繁體古文與現代文本，記錄 commit、URL、SHA-256、許可與抽取規則。原文只放 `.cache/`，提交清單與衍生統計。古文先以 chinese-poetry 的前兩個唐詩檔案作小規模試驗；現代文先以 UD Chinese GSD 的 wiki 文本作試驗，不宣稱代表所有古今中文。查到的《論語》《詩經》JSON 爲簡體，首版不引入繁簡轉換，故改用繁體唐詩。
2. **統計。** 復用既有字音推導及特殊字規則；保留每字不同全拼，等概率分配。按碼點計字與相鄰字對；標點、空白、未知字、文件邊界均斷開。報告字次／字種／字對覆蓋率、多音字佔比和缺字。
3. **預計算。** 建立單片段與槽位 1→2、2→3、3→1 的頻率矩陣。保留第三項爲跨字成本。每份語料除自身有效字數後再混合。
4. **評分。** 使用可配置 QWERTY 幾何和固定指法；首版計單鍵行位／伸展／手指成本、同指異鍵、同鍵重按、同手跨行，以及手指負荷集中懲罰。公開所有係數，以無單位代理成本報告，不能換算成提速比例。三鍵動作與真實 Rime 選字回放留作下一版。
5. **搜尋。** 以固定種子作多次模擬退火及局部下降，允許共鍵組間換鍵及移至閒置鍵。分別搜尋古文、現代文和各半混合的候選。按訓練成本選出各目標最佳種子，驗證／測試資料只作報告。
6. **驗證與交付。** 用小型人工可驗算文本驗證等概率、斷開、碼點處理、頻率守恆與矩陣成本；檢查重現性及所有候選的 3,809 音節無碰撞；運行既有測試。輸出可直接用於 `build:rime` 的 JSON、機讀報告與中文摘要。

資料切分：古文以章／詩爲單位作固定雜湊切分，現代文優先沿用上游 train/dev/test。這只是探索性保留集；古文同一作品跨集合，現代文也未必按來源文章分離，因此結果不等於跨作品泛化證明。重複全文不得跨集合；報告保留集分數，不用它調參。

首輪完成標準：能由固定來源重建統計，以同一組參數重現候選，且有現用／古文／現代／混合四表比較。候選保持試驗身分，不自動替換預設鍵表。後續再擴大語料、作作品級留出、校準成本、增加三鍵動作與允許重組共鍵。

## 首輪實作與使用

已實作下載、統計、評分、固定共鍵組搜尋及候選核驗；最終摘要見[鍵位優化結果](鍵位優化結果.md)。使用 Node.js 22 以上與 Python 3，無新增套件依賴。

```sh
npm run fetch:layout-corpora
npm run prepare:layouts
npm run search:layouts
npm test
npm run build:rime -- --layout .cache/layout-analysis/base-search/mixed.json --out dist/rime-mixed
```

- [下載器](../scripts/fetch_layout_corpora.py)：固定來源與 SHA-256 驗證；已有正確快取時不使用網絡。
- [統計器](../scripts/prepare_layout_corpora.mjs)：生成六組語料／切分矩陣與覆蓋率。
- [評分與搜尋模型](../scripts/layout_model.mjs)：頻率矩陣、QWERTY 成本、模擬退火及單步交換局部下降。
- [搜尋入口](../scripts/search_layouts.mjs)：預設每個目標 4 個種子、每次 20,000 步退火，再下降至無單步交換改進；支援 `--iterations`、`--seeds`、`--out`。
- [成本設定](../config/keyboard-cost.json)：所有代理係數及指法可修改，無記憶成本。
- [測試](../scripts/test_layouts.mjs)：小文本直接枚舉核對、守恆、斷開與搜尋重現性；逐候選重算成本及驗證無碰撞。

首版只評單鍵及二鍵銜接。未知字不猜讀音而斷開，缺字列表與頻率保留在統計中。即使保留集分數改善，仍需後續更廣語料及實打驗證。

## 三鍵動作試驗（2026-10-01）

已在獨立模組加入三鍵動作，保留首輪統計、程式及候選原樣以便比較；結論合併於[鍵位優化結果](鍵位優化結果.md)。

1. 從相同原文重新統計字內 123、跨字 231／312 的聯合頻率，逐集合核對文本雜湊及一／二階矩陣，確保與第一輪完全相同。同一字的各段取自同一讀音，字間仍按等概率獨立分配。
2. 加入同手折返及隔異手鍵後同指異鍵兩項懲罰；內滾、外滾、三次同指只作描述性指標。詳見[三鍵係數](../config/keyboard-trigram-cost.json)，它們是未經實打校準的假設。
3. 對古文、現代、混合目標各跑 4 個種子、20,000 步退火及局部下降。同一設定再跑 λ=0 對照組；第一個種子從相應舊候選出發，第二個從現用表出發，其餘從隨機排列出發。使用相同起點政策、種子、提案次數，局部下降直到收斂，不要求實際耗時完全相同。
4. 只按訓練成本選候選，將舊候選、零權重重搜、三鍵重搜放進同一新模型評分，另列原模型部分，避免把改變分數尺度當成改善。保留集已在前輪檢視過，明示爲探索性比較，不能宣稱全新盲測。
5. 固定候選重評 λ=0、0.5、1、2，不以保留集反調係數；如三鍵候選未勝過對照，也如實報告。

```sh
npm run fetch:layout-corpora
npm run prepare:trigrams
npm run search:trigrams
npm test
npm run build:rime -- --layout .cache/layout-analysis/trigram-search/trigram-mixed.json --out dist/rime-trigram-mixed
```

[三鍵統計器](../scripts/prepare_layout_trigrams.mjs)、[動作分類與增量搜尋](../scripts/layout_trigrams.mjs)、[試驗入口](../scripts/search_layout_trigrams.mjs)、[直接枚舉核對測試](../scripts/test_layout_trigrams.mjs)均無新增外部依賴。搜尋以受換鍵影響的矩陣項增量計分，測試以完整重算獨立核對其差額。
