# 鍵位優化結果

最終方案採用 **古今混合頻率優化 v1**。它是二鍵成本模型的混合語料重搜最佳候選，原代號 `control-mixed`；已統一寫入 [Rime 預設鍵表](../config/keyboards/default.json)、[推導方案](../prengQvm.js)及完整[鍵表](../data/keyboard.tsv)。原始試排另存爲 [baseline.json](../config/keyboards/baseline.json)。

## 選擇理由

所有比較均固定三段順序、既有共鍵分組及 24／23／21 用鍵數，多音字按不同中古全拼等概率分配，不計記憶成本。代理成本越低越好；它不是毫秒或實際提速比例。

| 混合測試集鍵表 | 二鍵模型成本 | 加入三鍵附加項後 | 二鍵同指異鍵率 | 三鍵折返率 | 隔鍵同指異鍵率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原始試排 | 3.2669 | 3.6485 | 10.08% | 8.82% | 6.04% |
| 第一輪混合候選 | 1.7446 | 2.1714 | 2.43% | 12.56% | 5.20% |
| **最終方案** | **1.7453** | **2.1034** | **2.85%** | 10.34% | 4.47% |
| 三鍵混合候選 | 1.8043 | 2.1339 | 3.00% | **9.58%** | **4.09%** |

第一輪候選在原二鍵模型下略低 0.04%，但加入三鍵動作後，最終方案低 3.13%。三鍵專門候選的折返及隔鍵同指異鍵最少，總成本卻比最終方案高 1.45%。三鍵附加權重改爲 0.5 或 2 時，最終方案仍在這三個混合候選中最低。因此它是目前較穩妥的綜合選擇。

這仍是探索結果：成本係數未經實打校準，搜尋是多種子模擬退火及局部下降，不保證全局最優。保留測試集已在探索過程中查看過，也不是全新盲測。

## 評分內容

基礎模型計算單鍵行位、伸展及手指成本，以及相鄰二鍵的同指異鍵、同鍵重按、同手跨行和手指負荷集中。三鍵試驗再涵蓋字內 `123`、跨字 `231` 和 `312` 三種窗口：

- 同手連續換指後方向折返，附加 0.8。
- 中間鍵屬異手、首末爲同指異鍵，附加 0.8 加 0.3 倍首末鍵距離。
- 內滾、外滾只統計，不預設獎懲。

全部係數見 [keyboard-cost.json](../config/keyboard-cost.json)及 [keyboard-trigram-cost.json](../config/keyboard-trigram-cost.json)。

## 重現

使用 Node.js 22 以上及 Python 3：

```sh
npm run fetch:layout-corpora
npm run prepare:layouts
npm run search:layouts
npm run prepare:trigrams
npm run search:trigrams
npm test
```

下載器先按固定 SHA-256 驗證外部檔案；正確快取存在時不重複下載。生成結果位於 `.cache/layout-analysis/`，不進入版本控制。預設搜尋每個目標使用 4 個固定種子、每次 20,000 步退火，再下降至沒有單次槽內交換可改善。

最終 Rime 方案直接執行：

```sh
npm run build:rime
```

全部 3,808 個聯集地位及補充「怎」已重新生成並驗證完整三鍵無碰撞。真實選字、上屏、個人指法及實際按鍵時間仍未納入模型。
